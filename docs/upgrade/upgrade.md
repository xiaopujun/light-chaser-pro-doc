# Web 端升级指南

本页面向 `lcp-server` Web 部署。本次文档核对的工程版本为 `2026.9.0`；服务器的实际版本和可用更新请以 **设置 → 关于**及部署包说明为准。

## 先确认部署方式

| 方式 | 保留的数据与配置 | 升级时要注意 |
| --- | --- | --- |
| 常规部署 | MySQL 数据库、`config/application.yml`、实际资源与 AI 存储目录 | `server.jar` 与同次构建的 `component-docs/` 应配套更新 |
| Docker app | 外部 MySQL、包根目录 `.env`、`config/`、`resource/` 与 `logs/` | 使用匹配主机架构的 app 包，保留数据目录及数据库连接 |
| Docker allinone | `.env`、`config/`、整个 `data/` | 数据库也在 `data/` 中；不可只替换资源子目录或随意更换 MySQL 基础版本 |

当前 Docker 入口没有“一键升级”或“备份”命令。跨版本、跨部署形态迁移前，应按目标包说明确认数据兼容性；不能把仅适用于同应用、同 MySQL 版本的目录搬迁直接当成跨版本升级流程。

## 升级前

1. 记录当前版本、部署路径、访问地址及端口。
2. 备份 MySQL 数据库、外部配置，以及实际使用的资源、AI 存储和密钥文件目录；资源路径可能自定义，不能只备份 JAR 所在目录。
3. 保留可回退的原部署包，并确认备份可读取。数据库若已发生结构迁移，回退时也需要匹配的数据库备份，不能只换回旧 JAR。
4. 在测试环境验证目标版本能加载现有项目和资源。

## 更新与验证

停止原实例后，按目标包的 [Web 部署说明](/deploy/web.md)部署。常规包必须保留 `server.jar` 同级的 `component-docs/`；完整解压部署包时，不要遗漏它。保留原配置的有效值，根据新模板补充必需项。

启动脚本提示进程已启动，不等同于站点已就绪。应实际检查：

- 登录、项目列表及已有项目能否打开。
- 图片、字体、视频、3D 模型和服务器组件能否加载。
- 数据库/API、模型配置与 AI 功能是否仍可用。
- 预览与原发布链接能否访问，密码和有效期是否符合预期。
- 日志中是否出现迁移、资源路径或组件文档读取错误。

## 与旧文档的区别

旧版指南中的 `2026.2.0`、macOS 资源修复、桌面自动更新和独立运行时打包说明属于其他交付方式。Web 更新由服务器维护者执行，浏览器收到更新提示并不代表服务器已经自动升级。
